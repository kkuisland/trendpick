# 글 작성 규칙

클라우드 루틴(자동 발행 에이전트)과 사람이 함께 따르는 규칙입니다.
에이전트는 매 실행마다 백지에서 시작하므로, 이 문서가 유일한 기준입니다.

## 1. 파일 위치와 형식

- 한국어: `content/posts/<슬러그>.md`
- 영어: `content/en/posts/<슬러그>.md`
- 슬러그는 영문 소문자·하이픈만. 4~6단어 (예: `chuseok-2026-ktx-srt-booking`)

프런트매터:

```markdown
---
title: 32자 내외, 핵심 검색 키워드를 앞쪽에
description: 70~110자. 핵심 답 + 클릭할 이유
date: YYYY-MM-DD
category: (아래 카테고리 목록 중 하나)
tags: [태그1, 태그2, 태그3]
keywords: [노리는 검색어1, 검색어2, 검색어3]
event: (선택) data/events.json 의 키
draft: false
---
```

**카테고리** — 한국어: `트렌드 이슈` `스포츠` `경제·머니` `IT·테크` `생활 정보` `이벤트 대비`
영어: `K-Drama` `Korean Food` `Culture` `Travel` `Trending`
(영문 글에 한국어 카테고리를 쓰면 안 됩니다.)

## 2. 본문 구조

1. 프런트매터 직후 **소제목 없이 3~4문장으로 핵심 답변**. 서론·인사말 금지 (추천 스니펫 대상)
2. 이벤트 키가 있으면 다음 줄에 `::event <키>`
3. `{{toc}}`
4. `{{ad}}` — **정확히 2회**. 핵심 답변 뒤 1회, 본문 중간 1회. `{{toc}}` 보다 뒤에 옵니다
5. `##` 소제목 4~7개. 소제목에도 검색 키워드를 자연스럽게
6. 마크다운 표 **최소 1개** (일정표·비교표·요금표)
7. 문단은 2~4문장. 목록 적극 활용
8. 관련 있는 기존 글 1~2개를 `[제목](/posts/슬러그/)` 로 내부 링크
9. 마지막에 FAQ 5~6개:

```markdown
::faq
Q: 질문?
A: 답변.

Q: 질문?
A: 답변.
::
```

## 3. 정확성 — 가장 중요

- **웹 검색으로 사실을 확인한 뒤 씁니다.** 날짜·금액·시행일·일정·요건처럼 독자가 그대로 행동에 옮길 정보는 반드시 검색합니다.
- 확인한 내용은 단정적으로 씁니다. **확정되지 않았거나 향후 공지 예정인 것만** 문장 끝에 `[확인 필요]`.
- 출처가 엇갈리면 공신력 있는 쪽(정부·공공기관·해당 기업 공식 발표)을 따르고 근거를 밝힙니다.
- **모르면 쓰지 않습니다.** 표현을 흐려서 넘어가지 마세요. 틀린 내용을 두루뭉술하게 쓰는 것이 안 쓰는 것보다 나쁩니다.
- 뉴스 본문·사진을 복사하지 않습니다. 사실을 확인해 자기 문장으로 정리합니다.
- 실존 인물의 발언을 인용할 때는 검색으로 확인된 것만 씁니다.

## 4. 쓰면 안 되는 주제

`scripts/plan.mjs` 가 기획 리포트에 🚫 로 표시합니다. 표시된 주제는 건너뜁니다.

- 재난·인명 피해, 범죄·수사·재판, 부고
- 의료 사고·감염병
- 국내 정치(편향 위험), 특정 종목 투자 판단
- 개인 사생활·논란, 인물 신상 캐기(프로필·재산·근황)
- **매일 바뀌는 값** — 오늘 날씨, 운세, 로또 당첨번호, 실시간 환율
  (단 "태풍 대비 요령", "장마철 준비"처럼 수명이 긴 주제는 괜찮습니다)

완성한 글의 제목·요약이 위에 해당하면 **파일을 만들지 말고 다음 후보로** 넘어갑니다.

## 5. 검수 보류 (draft: true 로 저장)

**기본은 발행(`draft: false`)입니다.** 검수 보류는 아래 다섯 가지뿐입니다 —
웹 검색으로 사실을 맞춰도, 독자가 글을 그대로 따라 했다가 틀리면 **돈·건강·권리를 되돌릴 수 없게 잃는 글**입니다.
판단은 `scripts/plan.mjs` 의 `reviewReason()` 과 같은 기준입니다.

| 분류 | 묶는 경우 | 묶지 않는 경우 (발행) |
|---|---|---|
| 의료·건강 | 증상 판단, 치료·복용·처방·용량 안내 | 연휴 문 여는 병원 찾는 법, 운동·생활 습관 일반 |
| 투자·대출 판단 | 특정 종목·코인·부동산 매수매도, 대출 금리·한도·갈아타기 권유 | 기준금리 발표 같은 경제 뉴스 정리 |
| 세금·법적 의무·받을 돈의 자격 | 세금 신고·공제, 과태료·위약금, 휴일근로 수당, 지원금 신청 자격 | 공휴일·연휴 날짜, 통행료 면제 기간처럼 공지 한 줄로 끝나는 사실 |
| 시험 당일 규칙·마감 | 입실 시각, 반입 금지 물품, 원서 접수 마감 | 시험 일정 소개, 합격 발표일 |
| 실존 인물 발언·평가 | 발언 인용, 의혹·비판·해명 | 선수·배우 이름이 나오는 경기·작품 소개 |

**숫자·일정·순위·가격·인물 이름이 나온다는 이유만으로 `draft: true` 로 묶지 않습니다.**
그런 글은 웹 검색으로 확인하고, 수치에는 출처(기관·언론사 이름)를 문장 안에 밝혀서 그대로 발행합니다.
확인이 안 되는 사실은 흐리게 쓰거나 검수로 미루지 말고 **그 문장을 빼거나, 그래도 안 되면 다른 주제를 고릅니다**(3장).

> 위 다섯 가지에 해당하면 공식 발표를 확인했더라도 `draft: true` 이고, 프런트매터에 `reviewReason:` 으로 분류 이름을 적습니다.
> 대기 글은 사장님이 어드민(`/admin/`) 「검수 대기」에서 읽고 발행·삭제합니다.

## 6. 제휴 링크

`data/affiliates.json` 에 **URL이 채워진 키만** `{{aff 키}}` 로 사용합니다. 없으면 넣지 않습니다.

- 주제와 링크 대상이 **실제로 맞을 때만**. 선물세트 링크는 선물 이야기에만, 상비약 이야기에는 넣지 않습니다
- **건강·의료·안전·재난 주제에는 제휴 링크를 넣지 않습니다.** 신뢰도가 우선입니다
- 한 글에 1~2개면 충분합니다
- 배치는 "구매 의도가 생긴 직후" — 판단 기준(가격대·선택 기준)을 먼저 주고 그다음에 링크
- 써보지 않은 상품의 후기·추천은 쓰지 않습니다. 고르는 기준을 줍니다
- `{{coupang}}` 은 사용하지 않습니다 (구버전)

대가성 고지는 빌드가 자동으로 넣으므로 본문에 쓰지 마세요.

## 7. 발행량

- **오늘 날짜는 한국시간(KST)입니다.** 샌드박스 시계는 세계 표준시(UTC)라 아침 7시 실행이 전날로 잡힙니다.
  날짜는 반드시 `TZ=Asia/Seoul date +%F` 로 확인하고, `date:` 와 커밋 메시지에도 이 날짜를 씁니다.
  (UTC 날짜로 "오늘 이미 썼다"고 판단해 하루를 통째로 건너뛴 적이 있습니다.)
- **회당 1편**, 하루 최대 1편 (`config/site.config.json` 의 `automation.maxPostsPerDay`)
- 오늘(KST) 날짜로 이미 정한 편수가 있으면 생성하지 않습니다. 검수 보류(`draft: true`) 글도 편수에 셉니다
- **쓸 만한 주제가 없으면 쓰지 않습니다.** 억지로 채우지 않는 것이 정상 동작입니다

## 8. 문체

- 존댓말. 과장·낚시성 표현 금지
- 검색자가 실제로 궁금해할 것(날짜·방법·비용·절차·비교)을 우선
- 경제 주제면 투자 자문이 아님을 본문에 명시 (경제·머니 카테고리는 빌드가 자동 삽입)
- 건강 주제면 전문가 상담 권고를 명시
- 영문 글은 번역이 아니라 **해외 독자 기준으로 따로 씁니다.** 한국어 용어는 로마자 표기 후 괄호에 한글 (예: songpyeon (송편))
