# 제휴 링크 연결 가이드 (쿠팡 파트너스 · 트립닷컴)

## 핵심 원칙: 글에는 키만, URL은 한 곳에만

글 안에는 `{{aff 키}}` 만 씁니다. 실제 URL·추적코드는 [data/affiliates.json](../data/affiliates.json) 한 파일에서만 관리합니다.

```markdown
{{aff coupang-chuseok-gift}}
```

이렇게 하면:

- 제휴 캠페인이 바뀌어도 **글을 하나도 건드리지 않습니다** (JSON 한 줄만 수정)
- **URL이 비어 있으면 아무것도 렌더링되지 않습니다** → 링크를 못 만든 상태에서 글을 먼저 발행해도 안전합니다
- 링크를 채워 넣는 순간, 그 키를 쓰는 **모든 글에 한꺼번에** 반영됩니다

---

## 1단계 — 쿠팡 파트너스에서 링크 만들기

1. [partners.coupang.com](https://partners.coupang.com) 로그인
2. 상단 **링크 생성** 메뉴
3. 목적에 맞는 유형 선택:
   - **검색 링크** — "추석 선물세트" 같은 키워드 결과 페이지로 보냄. **정보성 글에는 이게 가장 잘 맞습니다** (특정 상품을 추천하는 형식이 아니라 "골라볼 수 있는 목록"을 주는 것이라, 써보지 않은 상품을 추천하는 문제를 피할 수 있습니다)
   - **상품 링크** — 특정 상품 하나
   - **다이내믹 배너** — 자동 상품 추천 위젯 (아래 별도 설명)
4. 생성된 URL(`https://link.coupang.com/a/XXXXX`)을 복사

`data/affiliates.json`의 해당 키에 붙여넣습니다:

```json
"coupang-chuseok-gift": {
  "partner": "coupang",
  "title": "추석 선물세트 모아보기",
  "url": "https://link.coupang.com/a/XXXXX"
}
```

### subid 는 자동입니다

빌드할 때 URL에 `subid=<글-슬러그>` 가 자동으로 붙습니다. 쿠팡 파트너스 대시보드의 **서브 아이디별 리포트**에서 **어느 글이 수익을 냈는지** 바로 확인할 수 있습니다. 따로 설정할 것은 없습니다.

## 2단계 — 트립닷컴 링크 (대시보드 없이 자동)

트립닷컴 제휴는 **대상 주소에 제휴 식별 파라미터를 붙이는 방식**입니다. 계정의 `Allianceid`·`SID`를 [data/affiliates.json](../data/affiliates.json)의 `partners.tripcom.tracking`에 저장해 두었으므로, **평범한 trip.com 주소만 넣으면 추적 링크가 자동으로 완성됩니다.**

```json
"tripcom-jeju-hotel": {
  "partner": "tripcom",
  "title": "제주 숙소 요금 비교",
  "sourceUrl": "https://kr.trip.com/hotels/list?city=336"
}
```

빌드가 이렇게 바꿉니다:

```
https://kr.trip.com/hotels/list?city=336&Allianceid=10208899&SID=329172180&trip_sub1=글슬러그
```

`trip_sub1`에 글 슬러그가 자동으로 들어가 **어느 글에서 발생한 예약인지** 대시보드에서 구분됩니다.

> 대시보드에서 만든 단축 링크(`trip.com/t/XXXX`)를 쓰고 싶으면 `sourceUrl` 대신 `url`에 넣으세요. `url`이 있으면 그대로 사용합니다.

## (참고) 트립닷컴 링크를 대시보드에서 만드는 법

1. [kr.trip.com/partners/](https://kr.trip.com/partners/) 제휴 대시보드 로그인
2. **Link Builder**(링크 생성) 도구 사용
3. 원하는 페이지의 트립닷컴 URL(예: 나고야 호텔 목록)을 Custom Link 칸에 붙여넣어 **추적 링크로 변환**
4. 변환된 전체 URL을 그대로 복사해 `data/affiliates.json`에 붙여넣기

> **중요**: 추적 파라미터 이름을 직접 만들어 붙이지 마세요. 대시보드가 생성한 URL을 **통째로** 붙여넣어야 정확히 추적됩니다. 트립닷컴은 파라미터 체계가 계정·프로그램별로 다를 수 있습니다.

트립닷컴은 **30일 쿠키**라 클릭 후 한 달 안에 예약해도 실적이 잡힙니다. 여행 상품은 객단가가 높아 쿠팡보다 건당 수익이 훨씬 큽니다.

## 자동 점검 및 요청 (매일)

`scripts/affiliate-check.mjs`가 하루 3회 자동 실행되어:

1. **자동 생성 가능한 링크는 즉시 만듭니다** — 트립닷컴은 `sourceUrl`만 있으면 항상, 쿠팡은 API 키가 있고 권한이 활성화된 경우
2. **사람이 만들어야 하는 링크는 GitHub 이슈로 요청합니다** — 이슈가 생성·갱신되면 **GitHub이 저장소 소유자에게 메일을 보냅니다** (별도 SMTP 설정 불필요)
3. **링크가 없는데 수익화 기회가 있는 글**도 함께 알려줍니다

같은 제목의 열린 이슈가 있으면 새로 만들지 않고 본문만 갱신해 메일 스팸을 막습니다.

### 쿠팡 API 자동 생성 (조건부)

쿠팡 파트너스 Open API를 쓰면 링크 생성도 자동화됩니다. 단 **누적 판매액이 15만 원을 넘어야 API가 활성화**되므로, 그전까지는 대시보드에서 수동으로 만들어야 합니다.

조건을 충족하면 쿠팡 파트너스 → 도구 → 파트너스 API에서 키를 발급받아 등록하세요:

```bash
gh secret set COUPANG_ACCESS_KEY --repo kkuisland/trendpick
```

```bash
gh secret set COUPANG_SECRET_KEY --repo kkuisland/trendpick
```

키가 등록되면 `sourceUrl`이 있는 쿠팡 항목이 자동으로 딥링크로 변환됩니다. 키가 없거나 권한이 없으면 조용히 건너뛰고 이슈 요청으로 넘어갑니다.

## 3단계 — 글에 배치하기

이미 배치해 둔 곳:

| 글 | 위치 | 키 |
|---|---|---|
| 2026 추석 연휴 총정리 | "추석 선물" 섹션 (가격대별 표 아래) | `coupang-chuseok-gift` |
| 2026 아시안게임 일정 | "직관을 계획한다면" 섹션 | `tripcom-nagoya-hotel` |
| Chuseok 2026 (영문) | 여행 팁 섹션 | `tripcom-korea-hotel` |

### 배치 원칙

- **구매 의도가 생긴 직후**에 놓습니다. 글 맨 위나 맨 아래가 아니라, "뭘 사야 하지?"라는 생각이 드는 문단 바로 다음입니다.
- **판단 기준을 먼저 주고** 링크를 놓습니다. 위 예시들은 모두 가격대별 표나 선택 기준을 설명한 뒤에 링크가 옵니다. 써보지 않은 상품을 "추천"하는 대신 **고르는 기준**을 주는 방식이라 신뢰도를 해치지 않습니다.
- **한 글에 1~2개**면 충분합니다. 많이 넣는다고 수익이 비례해 늘지 않고, 체류시간만 떨어집니다.

## 대가성 고지는 자동입니다

**제휴 링크가 실제로 렌더링된 글에만** 대가성 고지가 글 상단에 자동으로 붙습니다. 프런트매터에 뭘 적을 필요가 없습니다 — 법적 의무를 사람의 기억에 의존시키지 않기 위한 설계입니다.

- 쿠팡을 쓴 글 → 쿠팡 파트너스 고지 문구
- 트립닷컴을 쓴 글 → 트립닷컴 고지 문구 (영문 글은 영문 문구)
- 둘 다 쓴 글 → 두 문구 모두

공정위 표시·광고 심사지침은 **글마다** 고지를 요구합니다. About 페이지 고지만으로는 부족합니다. 고지 문구를 수정하려면 `data/affiliates.json`의 `partners.<이름>.disclosure` 를 고치면 전체 글에 반영됩니다.

## 성과 측정 (GA4)

모든 제휴 링크에 `rel="sponsored"` 가 붙고, 클릭 시 GA4로 `affiliate_click` 이벤트가 전송됩니다:

| 파라미터 | 내용 |
|---|---|
| `affiliate_partner` | `coupang` / `tripcom` |
| `affiliate_key` | 링크 키 (예: `coupang-chuseok-gift`) |
| `page_path` | 클릭이 발생한 글 |

**GA4 측정 ID가 설정되어야 작동합니다** (`config.analytics.ga4`). 아직 미설정 상태입니다.

측정 ID를 넣으면 이렇게 볼 수 있습니다:

- **글별 제휴 클릭률** = `affiliate_click` ÷ 해당 글 조회수 → 링크 배치가 잘 됐는지 판단
- **제휴사별 클릭 비중** → 쿠팡 vs 트립닷컴 중 어디에 집중할지 판단
- 실제 **구매 전환·수익**은 각 제휴 대시보드에서 확인 (쿠팡은 subid로 글 단위 확인 가능)

두 숫자를 맞춰 보면 "조회 1000회당 실제 수익"이 나옵니다. 이 값이 광고 RPM보다 높은 글이 밀어야 할 글입니다.

## 새 링크 추가하기

`data/affiliates.json`의 `links` 에 항목을 추가하고, 글에서 `{{aff 새키}}` 로 호출하면 끝입니다.

```json
"tripcom-jeju-hotel": {
  "partner": "tripcom",
  "title": "제주 숙소 요금 비교",
  "url": "https://…(대시보드에서 생성한 URL)",
  "note": "메모 — 빌드에는 영향 없음"
}
```

`title` 은 버튼에 표시되는 문구입니다. 영문 글용으로는 `titleEn` 을 추가하면 됩니다.

## 쿠팡 다이내믹 배너 (별도)

자동 상품 추천 위젯은 개별 링크와 다른 방식입니다. `config/site.config.json` 에서 설정합니다:

```json
"coupang": { "enabled": true, "dynamicBannerId": "배너ID", "trackingCode": "추적코드" }
```

글에서는 `{{coupang}}` 로 호출합니다. 다만 위젯은 문맥과 무관한 상품이 나올 수 있어, **정보성 글에는 `{{aff}}` 검색 링크가 대체로 성과가 좋습니다.**

## 어드민 페이지로 붙이기 (가장 쉬운 방법)

**https://ktrend.kr/admin/** 에서 글을 고르고 링크만 붙여넣으면 됩니다. 마크다운을 고칠 필요가 없습니다.

1. **글 선택** — 발행된 글이 모두 나옵니다 (영문은 `[EN]` 표시)
2. **제휴사·문구·링크 입력**
   - 쿠팡: 파트너스에서 만든 `link.coupang.com/a/...` 링크를 그대로
   - 트립닷컴: **평범한 trip.com 주소**만 넣으면 추적 파라미터가 자동으로 붙습니다
3. **넣을 위치** (선택) — 비워두면 FAQ 바로 앞. 소제목 일부를 적으면 그 섹션 뒤에 들어갑니다
4. **저장** → `postLinks` JSON 이 나옵니다. `data/affiliates.json` 에 넣고 커밋하면 다음 배포에 반영됩니다

`robots.txt` 와 `noindex` 로 검색엔진에서 제외되어 있습니다.

### postLinks 가 하는 일

```json
"postLinks": {
  "글-슬러그": {
    "partner": "coupang",
    "title": "버튼 문구",
    "url": "https://link.coupang.com/a/...",
    "afterHeading": "선택 — 이 소제목 뒤에 넣기"
  }
}
```

빌드가 해당 글에 제휴 블록을 자동으로 끼워 넣습니다. subid(글 슬러그)와 대가성 고지도 자동입니다.

- 기존 링크를 재사용하려면 `{ "key": "coupang-chuseok-gift" }` 처럼 키만 적어도 됩니다
- **본문에 `{{aff}}` 로 직접 넣은 글은 건드리지 않습니다** (수동 배치 우선)
- URL 이 잘못됐거나 파트너가 비활성이면 아무것도 렌더링하지 않고 빌드 경고만 남깁니다

### 어떤 링크를 넣을지 추천해 줍니다

글을 고르면 아래에 추천이 뜹니다. 세 가지 중 하나입니다.

| 표시 | 뜻 |
|---|---|
| 💡 **추천: 쿠팡/트립닷컴** | 그 글에 맞는 제휴사와 아이디어. 기존 링크가 맞으면 **"○○ 쓰기"** 버튼으로 바로 연결 |
| **추천 없음** | 구매로 이어질 맥락이 뚜렷하지 않음. 억지로 넣지 않는 편이 낫습니다 |
| ⚠️ **넣지 않는 편이 좋음** | 의료·건강, 재난·안전, 제도 안내 — 신뢰도가 우선입니다 |

판단 근거는 세 가지입니다.

1. **이벤트의 수익화 메모** — `data/events.json` 의 `monetize` (예: 추석 → "선물세트·귀성 용품 쿠팡 연계, 여행 상품 제휴")
2. **제목·키워드의 구매 의도** — 여행·숙소·항공은 트립닷컴, 선물·용품·세일은 쿠팡 (영문 글은 travel/hotel/gift 같은 영어 표현으로 판단)
3. **넣으면 안 되는 주제인지** — `scripts/lib/recommend.mjs` 의 `BLOCK`

기존 링크 추천은 **제목·메모가 겹치는 정도로 점수를 매겨 상위 2개**만 보여줍니다. 영문 글에는 영문 표기(`titleEn`·`labelEn`)가 준비된 링크만 추천합니다.

기준을 바꾸려면 `scripts/lib/recommend.mjs` 를 수정하세요.

### 바로 저장되게 하기 (Railway 설정)

기본은 읽기 전용입니다. 아래 두 값을 Railway 환경변수에 넣으면 어드민에서 **저장 버튼만으로 반영**됩니다.

| 변수 | 값 |
|---|---|
| `ADMIN_PASSWORD` | 원하는 관리자 비밀번호 |
| `GITHUB_TOKEN` | 저장소 `contents: write` 권한 토큰 |
| `GITHUB_REPO` | (선택) 기본값 `kkuisland/trendpick` |

토큰은 [Fine-grained PAT](https://github.com/settings/personal-access-tokens/new) 으로 만드시고, 저장소를 `kkuisland/trendpick` 하나로 제한한 뒤 **Repository permissions → Contents: Read and write** 만 켜세요.

저장하면 `data/affiliates.json` 의 `postLinks` 가 GitHub 에 커밋되고, Railway 가 이를 감지해 다시 배포합니다(1~2분).

**동작 방식과 안전장치**

- Railway 컨테이너의 파일은 재배포 때 사라지므로, 파일을 쓰지 않고 **GitHub 에 커밋**합니다
- 비밀번호는 브라우저 탭에만 저장되고(`sessionStorage`) 탭을 닫으면 사라집니다
- 비밀번호 비교는 타이밍 공격에 안전한 방식이고, 10분에 10회 실패하면 잠깁니다
- `postLinks` 외의 내용은 건드리지 않으며, `http/https` 가 아닌 주소와 이상한 slug 는 거부합니다
