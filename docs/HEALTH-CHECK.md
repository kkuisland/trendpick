# 사이트 건강검진

클라우드 루틴 「두 사이트 건강검진」이 매일 이 문서대로 케이트렌드(ktrend.kr)와 AI Wave(aiwave.kr)를 점검한다. 사람이 직접 돌릴 때도 같다.

```bash
node scripts/health-check.mjs              # 매일 점검
node scripts/health-check.mjs --external   # 본문의 외부 링크(공식 출처)까지. 주 1회
node scripts/health-check.mjs --json       # 결과를 JSON 으로
```

- 점검 대상은 `config/health-check.json`. 확인할 파일·주소 넘김·어드민 주소를 바꾸려면 여기만 고친다.
- npm 패키지가 필요 없다. 요청은 curl 로 보낸다 (클라우드 샌드박스의 프록시를 따르게 하려고).
- **읽기만 한다.** 사이트나 저장소를 바꾸지 않는다. 두 사이트를 합쳐 하루 약 220번 요청하고, 15초쯤 걸린다. 서버 부담은 무시할 수준이다.
- 종료 코드: `0` 이상 없음, `1` 주의만 있음, `2` 문제 있음.

## 무엇을 보나

| 항목 | 문제(❌)로 보는 것 | 주의(⚠️)로 보는 것 |
| --- | --- | --- |
| 첫 화면 | 연결 안 됨, 200 이 아님 | |
| 필수 파일 | robots.txt·ads.txt·rss.xml·공유 썸네일이 없음, ads.txt 에 게시자 ID 없음, robots.txt 가 사이트 전체를 막음 | |
| 주소 넘김 | www → 루트 영구 이동이 깨짐 | AI Wave 의 www (DNS 미설정, 아래 참고) |
| 어드민 | 로그인 없이 열림 (200) | Cloudflare Access 로그인 화면으로 넘어가지 않음 |
| 사이트맵의 모든 페이지 | 연결 실패, 4xx·5xx, 제목 없음, `[확인 필요]` 노출 | 다른 주소로 넘어감, 3초 넘게 걸림, 설명 없음, 사이트맵에 있는데 noindex, 본문이 거의 없음 |
| 페이지 안의 내부 링크·도구 스크립트·이미지 | 404 등 깨짐 | 연결 실패 |
| 새 글 (AI Wave) | | 사이트맵 최신 갱신이 2일 넘게 없음 → 매일 발행 루틴 확인 |
| 외부 링크 (`--external`) | | 404·410 (공식 출처 주소가 바뀜) |

## 루틴 절차

1. `node scripts/health-check.mjs` 를 실행한다. 오늘이 월요일(KST)이면 `--external` 을 붙인다.
2. **연결 실패가 있으면 오탐인지 먼저 가린다.** 클라우드 샌드박스에서 사이트로 가는 길이 막혀 연결 실패가 나는 일이 있었다. 사이트가 실제로 멈춘 것과 구분해야 한다. 그 사이트 첫 화면을 WebFetch 로 한 번 더 연다.
   - WebFetch 로 열리면 "점검 경로 문제, 사이트는 정상"으로 적고 알림을 보내지 않는다.
   - WebFetch 로도 안 열리면 진짜 장애로 본다.
3. 2번을 거친 뒤에도 ❌ 가 남으면 **휴대폰 알림(PushNotification)** 을 보낸다. 사이트 이름, 문제 건수, 가장 심각한 것 한두 개를 한두 줄로 적는다. ⚠️ 만 있으면 알림을 보내지 않고 보고에만 적는다.
4. 고치지 않는다. 저장소를 수정·커밋·푸시하지 않는다. 고치는 일은 사람이나 다른 세션이 보고를 보고 한다.
5. 보고 (한 줄씩):
   - 결과: 이상 없음 / 주의 n건 / 문제 n건 (알림 보냄 여부)
   - 문제: 항목별 한 줄 (사이트, 내용, 주소)
   - 주의: 항목별 한 줄. 아래 「알려진 주의」에 있는 것은 "(알려진 항목)"이라고 붙인다.
   - 점검 경로 문제가 있었다면 그 사실

## 알려진 주의 (고칠 때까지 매일 뜬다)

- **AI Wave 의 www.aiwave.kr 가 열리지 않음:** DNS 레코드가 없다. Cloudflare 에 `www` 레코드와 루트로 보내는 리디렉션 규칙을 넣으면 사라진다. 케이트렌드에는 같은 설정이 이미 있다.
- **AI Wave /support 본문이 짧음:** 후원 안내 페이지라 짧은 것이 정상이다.
